# OpenCV 与 PCL 联动说明

## 立即体验

启动 `Run-Demo.cmd`，或打开 `PCLDemo.sln` 后按 F5，切换到“OpenCV + PCL 联动”页签。

默认已生成 320×240 的配准 RGB-D 示例：背景平面、红色矩形、绿色圆形、蓝色三角形、颜色纹理、深度噪声和一个小孔洞。上方比较输入图与处理图，下方查看带像素辅助色的三维结果。

## 实验一：按颜色选择目标，再用 PCL 处理

1. 选择“HSV 颜色分割”，H 下界 170、上界 10，点击执行。
2. 观察红色目标对应的三维点云，点击“发送至 PCL 工作区”。
3. 在 PCL 页执行体素降采样、离群点滤波等算法。
4. 返回联动页，选择“PCL 点云 → 深度图”并执行，查看三维处理结果的深度回投影。

发送结果会替换 PCL 工作区的原始与当前点云，清空旧处理链和目标云。原 RGB-D 图像仍保留在联动页。

前 9 项算法每次从本页加载的原始 RGB-D 输入开始，不会因重复点击而累计图像滤波；第 10 项读取 PCL 当前结果。

## 实验二：轮廓与三维尺寸

选择“轮廓 / 包围框 → 三维尺寸”，使用默认前景区间 0.2~2.3 米和最小面积 100 像素。

执行后能看到三个二维包围框与对应点云，日志显示每个目标的点数和相机坐标系下的 XYZ 轴向范围。先按深度提取前景，再做开运算和轮廓筛选；接触的前景可能被合并。

这里的尺寸是相机坐标轴方向的包围范围，受姿态、遮挡、深度噪声和采样影响，不是旋转不变的物体真实长宽高。

## 实验三：平滑、边缘和特征

- 中值滤波：浮点深度仅支持 3×3 或 5×5 核；原无效位置仍为 0。
- 双边滤波：默认深度 sigma 为 0.04 **米**，空间 sigma 使用**像素**。先临时修补无效邻域减少零值污染，完成后恢复原无效掩膜，不把补洞值输出成真实点。
- 深度阈值：用 `inRange` 选择前景像素并生成点云。
- 形态学：开运算去小噪声，闭运算连接小间隙，只作用于掩膜，没有真实深度的位置仍不会生成点。
- Canny：RGB 转灰度、高斯平滑、边缘检测、深度关联。颜色纹理也会产生边缘，不能将所有结果都当成几何边界。
- ORB：检测关键点并计算 32 字节二进制描述子，再关联有效深度；不执行特征匹配、PnP、粗配准或识别。

## 加载自己的 RGB-D 图像

先设置相机内参与“加载时：深度单位 / 米”，再点击“加载 RGB + 深度”，依次选择颜色图和深度图。

- RGB 使用常见 8 位颜色图，内部为 OpenCV BGR 顺序。
- 深度必须是单通道 **16 位无符号图**或**32 位浮点图**，不能用普通伪彩深度截图代替。
- 16 位深度按“单位 / 米”换算，默认 1000 表示毫米；32 位浮点深度直接按米解释。
- 推荐 16 位 PNG；其他格式取决于本机 OpenCV 编解码器。
- 深度 0、负值和非有限值均视为无效。
- 两图必须尺寸一致，且已经配准到同一像素坐标系；只有尺寸相同并不足以保证配准。
- fx、fy、cx、cy 应来自相机标定，并对应当前分辨率。缩放输入时，内参也应相应缩放。
- 本例不自动标定、不去畸变、不推断焦距，也不估计 RGB 与深度相机之间的外参。

调整内参后重新执行即可；深度单位只在加载 16 位文件时使用，修改后应重新加载文件。

## 坐标与双向投影

```text
Z = 深度，单位为米
X = (u - cx) × Z / fx
Y = (v - cy) × Z / fy
```

相机坐标系为 X 向右、Y 向下、Z 向前。深度 Z 是相机轴向距离，不是点到相机中心的欧氏距离。

回投影使用逆公式。多个点落在同一像素时只保留最近 Z；视野外、相机后方和深度范围外的点被排除。程序不会给任意世界坐标点云自动寻找观察姿态，应确保输入云已在正确相机坐标系下。

## 颜色与导出

反投影后的辅助 RGB 与 XYZ 按同一顺序保存，在联动页和刚发送到 PCL 时显示。现有 PCL 算法继续以 `PointXYZ` 工作，通常不会传播颜色；原有点云导出仍只写 XYZ。

- “导出处理图 PNG”：保存右侧处理图、伪彩深度、掩膜、框或特征图。
- “导出深度 PNG / 毫米”：保存真实 16 位单通道深度，不是伪彩图；无效或被掩膜排除的像素为 0，量化步长 1 毫米。
- 超过 65.535 米的深度拒绝导出为毫米 16 位 PNG，避免溢出。
- 图像通过 Qt Unicode 文件 API 加 `imdecode / imencode` 读写，支持中文路径。

## 规模与运行

像素步长 2 表示每隔 2 行、2 列取样，大约保留四分之一像素。单图上限 4,194,304 像素，生成云上限 500,000 点，较大输入需提高步长。

ORB 不使用全局步长，而是按真实关键点像素关联深度；回投影逐像素保留最近点。后台计算时禁用本页数据修改，失败会保留原有图像和点云；运行中关闭主窗口会提示等待完成。

## 源码和配置

| 文件 | 内容 |
| --- | --- |
| `src/RgbdAlgorithms.h/.cpp` | 10 个算法、数据结构、示例生成、I/O、反投影与 Z-buffer |
| `src/RgbdPanel.h/.cpp` | 参数、相机内参、图像/点云预览、后台任务与发送 |
| `src/CvSelfTest.cpp` | 数值、图像读写和双向 UI 流程验证 |
| `config/OpenCV.props` | 分别链接 `opencv_world500d.lib` 与 `opencv_world500.lib` |
| `scripts/Environment.ps1` | OpenCV、PCL、Qt 的进程 DLL 搜索路径 |

VS 的“OpenCV PCL Sources / Headers”分组中可以直接阅读新源码。新增控件没有声明新信号，不增加 moc 自定义生成项，继续沿用已修复的统一生成目标。

本机 OpenCV 5 将 `contourArea`、`boundingRect` 等接口放在 `opencv2/geometry.hpp`，示例已包含对应头文件。

程序默认使用 CPU 路径，不要求 GPU；OpenCV 日志保留警告和错误，隐藏可选插件探测的 INFO 消息。运行依赖为本机已安装的 `opencv_world500[d].dll`，不需要复制或修改系统环境变量。
